# 翻译审核台（tools/review）

给词表校对用的本机可视化工具。零第三方依赖（只用 Python 标准库 + 浏览器），
随仓库分发，`python tools/review/review_server.py` 就能跑。

```
python tools/review/review_server.py                 # 默认 127.0.0.1:8765，自动开浏览器
python tools/review/review_server.py --no-browser    # 不开浏览器
python tools/review/review_server.py --port 9000     # 指定首选端口
python tools/review/review_server.py --selftest      # 只跑一致性自检后退出
```

Windows 上如果 8765 报 `WinError 10013`，**不是权限问题**，是该端口落在
Hyper-V / WSL 的保留段里（本机 8525–9024 整段被占）。工具会自己读
`netsh interface ipv4 show excludedportrange` 绕开，并在启动时打印真实地址。

## 它替你干什么

词表 4800 多条、单文件 400 KB，直接读 JSON 校对不现实。这个工具把它摊成
**可检索、可筛选、可按风险排序**的表格，并在你改的时候保证 diff 干净。

### 五个页签

| 页签 | 用途 |
|---|---|
| **词条** | 主战场：搜索 / 按类型与作用域筛选 / 按风险标签筛选 / 逐条编辑 |
| **运行期清单** | 读插件目录里的 `missing.json` / `untranslated.json`，给出**近似**的通路判定 |
| **不一致清单** | 同原文多译文、忽略大小写重复键 —— 两张「该统一而没统一」的清单 |
| **体检报告** | 把 `tools/check_data.py` 的规则跑一遍，错误 / 警告 / 提示三档 |
| **文件与部署** | 仓库与运行目录的 md5 对照 + 一键把数据同步到游戏 |

### 风险标签

审核的价值主要在这里 —— 不用从第一条读到最后一条。

| 标签 | 档 | 含义 |
|---|---|---|
| 引入原文没有的括号 | 高 | 译名规范禁止；`check_data.py` 会直接判失败 |
| 占位符多于原文 | 高 | 模板键的 `\u0001` 是原文字符占位符，多了会回填错位 |
| 大小写重复键 | 中 | 运行时是 `OrdinalIgnoreCase` 字典，译文不同则静默覆盖 |
| 同原文多译文 | 中 | 同一段英文应有唯一译文；只有目标代号 identity 与作用域分歧是刻意例外 |
| 译文首尾空白 | 中 | 与原文的首尾空白不一致 |
| 出现在运行期清单 | 中 | 实机 `missing/untranslated` 里出现过 |
| 译文含拉丁字母 | 低 | 可能是未译尽，也可能是刻意保留的型号/缩写（当前 1092 条，多数该保留） |
| 译文不含中文 | 低 | identity 键或刻意保留项 |
| 译文等同原文 | 低 | 刻意的 identity，值得确认是否真有必要 |
| 译文显著偏长 | 低 | 显示宽度超原文 3 倍，短槽位标签有撑破风险 |

### 两个校对短标签的抓手

- **宽度**：详情面板显示「原文宽度 → 译文宽度」（CJK 记 2、其余记 1）。
  固定宽度槽位被撑破就是这里超了，超出 1.6 倍会标黄。
- **同组键**：详情面板底部并排列出同作用域（裸键则取文件顺序上的邻居）的兄弟条目。
  项目约定是「短槽位标签按同组兄弟的字数定长」，对着这一列改最省事。

### 占位符怎么看

`\u0001` 是不可见控制字符，编辑器里统一显示成 **`␁`**，暂存时自动还原。
注意方向性：模板的译文允许占位符**少于**原文（把 `␁` 改写成字面 `<b>…</b>` 是合法写法，
实测有 12 条这么做）；只有**多**出来才会回填错位。

## 写盘的安全边界

改动词表必须走 **暂存 → 预览 → 保存** 三步，前端不直接改文件。

1. **默认只读**，只有点「保存改动」才写盘。
2. 写盘前自动备份到 `data/.backups/translation.json.<时间戳>`（保留最近 20 份，已 gitignore）。
3. **只动该动的行**：未编辑的键那一行逐字节不动 —— diff 精确等于你改的那几条。
   这是刻意的：词表靠「一键一行、按码点升序」保证补词条的 diff 可读，
   整表重排会造出几千行假 diff、让 review 失效。
4. 保存后立刻复核：合法 JSON、键仍按码点升序、无字面重复键、无 BOM、纯 LF、
   行数与条目数一致、未触碰行未变。**任一条不成立就自动回滚**并从备份还原。
5. 新增的键按码点升序插到正确位置（二分，不重排其它行）；删除会处理尾逗号。

序列化统一走 `json.dumps(x, ensure_ascii=False)` —— 这恰好复现仓库既有风格
（控制字符转义成 `\u0001`，中文原样保留）。`--selftest` 会把整张表逐行比对一遍来
证明风格没漂移；改完本工具先跑它。

## 自检

```
python tools/review/review_server.py --selftest
```

会做四件事：

1. **序列化往返**：既有 4850 行逐行用 `dumps_line` 复现，必须 100% 逐字相同。
2. **在临时副本上真跑一次保存**：编辑 1 条 + 新增 1 条，核对最小 diff 恰好 3 行
   （改 1 得 `-`/`+` 各一、新增 1 得 `+` 一）、未触碰行 0 行被动。
3. **拒绝空改动**、非法键给出提示而非静默。
4. **真词表 md5 必须不变** —— 自检绝不允许碰到真文件。

## 与游戏的关系

- 工具只改 `data/*.json`。改完在游戏里按 **F11 →「重新加载翻译文件」**即可生效，不必重启。
- 但若这一轮同时改了 `src/` 下的 C#，那是 DLL 变更，**必须重启游戏**。
- 「保存后自动同步到运行目录」勾选后，保存成功会顺带把数据推到
  `BepInEx/plugins/NuclearOptionChineseLocalizationPatch/`（与
  `dotnet build -t:DeployData` 同一语义，**只推数据、不碰 DLL**）。

## 隐私

工具只在本机 `127.0.0.1` 监听，并校验 `Host` 头挡掉 DNS rebinding。
运行期清单里的玩家昵称**不要**写进 `data/exclusions.json` —— 那个文件随仓库公开分发。

运行期清单

这是近似判定，不代表流水线结论。 这里只查「键在不在表里」「作用域/文本在不在排除名单里」「表里有没有包含这段文字的键」， 没有复刻运行时的片段拼接 / 切片 / 前缀尾缀匹配 —— 那部分会让一批本来能翻的 条目被判成缺口（历史上静态比对的误报率约 23%）。所以分了四档： 已有通路 · 疑似有通路（表里存在包含它的键，多半是拼接）· 刻意保留 · 可疑缺口。 最后两档才值得人工看，而且玩家名与动态呼号会必然落在「可疑缺口」里——那是正常的， 按项目约定不登记。

同原文多译文

同一段英文在表里应当只有一个译文。刻意例外有两种： 目标代号 identity（[TargetCode]BLD → BLD，保持英文） 与 作用域语义分歧（deployed 反推展开 / 起落架放下）。 其余都属于「该统一而没统一」。

忽略大小写重复的键

运行时是 OrdinalIgnoreCase 字典，译文不同则后者静默覆盖前者 ——这是会真出问题的；译文相同则只是历史冗余。
